# Rendering Validation

This document is the durable validation ledger for the terminal rendering
implementation described in [rendering-spec.md](rendering-spec.md). It records
which requirements are covered by executable evidence, which are represented
in the deterministic gallery, and which still require an interactive terminal
observation.

The gallery and tests use only fixed inputs. They do not contact the Copilot
SDK, read credentials, or serialize the machine's current working directory.
The generated fixture uses `WORKSPACE` for path values and fixed IDs, dates,
model names, clocks, and tool payloads.

## Evidence Status

| Status | Meaning |
| --- | --- |
| `automated` | A focused executable test proves the complete row. |
| `gallery` | The production renderer is serialized at widths `20`, `40`, `80`, and `120`; the normal compare test detects drift. |
| `partial` | Some behavior is covered, but at least one subcase in the specification remains open. |
| `manual` | The behavior depends on a real terminal, focus, resize, scrollback, or SDK session. |
| `unverified` | The rendering specification explicitly leaves the behavior unresolved. |

## Deterministic Gallery

The gallery is generated by the test-only module
`src/tui_rendering_fixtures.rs` and committed at
`tests/fixtures/rendering/gallery.txt`. It calls the production transcript
renderer and `tui::draw` against ratatui `TestBackend` buffers. Each transcript
row records text, display width, foreground/background color, and modifiers;
each full-screen app fixture records every buffer row and contiguous style run.

The gallery has 50 named sections:

| --- | --- |
| User | `user-short-wrapped-hard-newline-unicode`, `user-truncation-10001` |
| Assistant and Markdown | `assistant-streaming-partial`, `assistant-nested-no-dot`, `markdown-headings-emphasis-links-lists`, `code-known-language`, `code-unknown-language-plaintext`, `table-aligned-wrapped-fallback` |
| Reasoning, notices, and subagents | `reasoning-collapsed`, `reasoning-expanded`, `notice-warning-error-diagnostic`, `notice-error`, `notice-diagnostic`, `notice-approval-resolved`, `subagent-task-top-level`, `subagent-task-nested` |
| Tool progress and results | `tool-progress-live-output`, `tool-result-ansi-success`, `tool-result-error`, `bash-truncation-verbose-off`, `bash-truncation-verbose-on`, `edit-diff-context-and-words` |
| Tool header states | `tool-header-queued`, `tool-header-running`, `tool-header-success`, `tool-header-error`, plus the four `-macos` variants and `tool-result-ansi-success-macos` |

The gallery is compared during ordinary test runs. Regeneration is opt-in and
ignored by default so a normal test cannot rewrite the committed artifact.

### Gallery Commands

Run these commands from the repository root in PowerShell.

```powershell
cargo test --lib tui::rendering_fixtures::committed_rendering_gallery_matches_production_renderer --quiet
cargo test --lib tui::rendering_fixtures::rendering_gallery_generation_is_deterministic --quiet
```

Regenerate only after reviewing the production rendering change:

```powershell
try {
    $env:PICOPILOT_REGENERATE_RENDERING_FIXTURES = '1'
    cargo test --lib tui::rendering_fixtures::regenerate_rendering_gallery -- --ignored --quiet
    if ($LASTEXITCODE -ne 0) { throw 'gallery regeneration failed' }
} finally {
    Remove-Item Env:PICOPILOT_REGENERATE_RENDERING_FIXTURES -ErrorAction SilentlyContinue
}
```

Prove regeneration is idempotent. The two hashes must be equal and the final
compare must pass:

```powershell
$fixture = 'tests/fixtures/rendering/gallery.txt'
try {
    $env:PICOPILOT_REGENERATE_RENDERING_FIXTURES = '1'
    cargo test --lib tui::rendering_fixtures::regenerate_rendering_gallery -- --ignored --quiet
    if ($LASTEXITCODE -ne 0) { throw 'first gallery regeneration failed' }
    $first = (Get-FileHash $fixture -Algorithm SHA256).Hash

    cargo test --lib tui::rendering_fixtures::regenerate_rendering_gallery -- --ignored --quiet
    if ($LASTEXITCODE -ne 0) { throw 'second gallery regeneration failed' }
    $second = (Get-FileHash $fixture -Algorithm SHA256).Hash
    if ($first -ne $second) { throw "gallery is not idempotent: $first <> $second" }
} finally {
    Remove-Item Env:PICOPILOT_REGENERATE_RENDERING_FIXTURES -ErrorAction SilentlyContinue
}

cargo test --lib tui::rendering_fixtures::committed_rendering_gallery_matches_production_renderer --quiet
```

The focused compare test must fail if the committed fixture is deliberately
changed. Perform that check only on a clean or otherwise understood worktree,
and always restore the original bytes:

```powershell
$fixture = 'tests/fixtures/rendering/gallery.txt'
$backup = Join-Path $env:TEMP "picopilot-gallery-$PID.txt"
Copy-Item $fixture $backup -Force
try {
    $text = [System.IO.File]::ReadAllText((Resolve-Path $fixture))
    $text = $text.Replace('picopilot-rendering-gallery-v1', 'picopilot-rendering-gallery-BROKEN')
    [System.IO.File]::WriteAllText((Resolve-Path $fixture), $text)
    (Get-Item $fixture).LastWriteTime = Get-Date

    cargo test --lib tui::rendering_fixtures::committed_rendering_gallery_matches_production_renderer --quiet
    if ($LASTEXITCODE -eq 0) { throw 'compare unexpectedly passed with a corrupted fixture' }
} finally {
    Copy-Item $backup $fixture -Force
    Remove-Item $backup -Force -ErrorAction SilentlyContinue
}

# `include_str!` is compile-time input; touch the restored file so Cargo does
# not reuse the intentionally corrupted test binary from its incremental cache.
(Get-Item $fixture).LastWriteTime = Get-Date
cargo test --lib tui::rendering_fixtures::committed_rendering_gallery_matches_production_renderer --quiet
```

The expected failure includes a focused unified diff headed `committed
gallery` and `production rendering`. A failed mismatch probe is evidence that
the guard is active; it is not a product-test failure after the fixture is
restored.

## Focused Validation Matrix

Run the narrow checks before the full suite:

```powershell
cargo test --test screen_model --quiet
cargo test --test ansi_sanitization --quiet
cargo test --lib markdown::tests --quiet
cargo test --lib file_diff::tests --quiet
cargo test --lib palette::tests --quiet
cargo test --lib tui::tests --quiet
cargo test --lib tui::rendering_fixtures --quiet
```

Then run the repository checks:

```powershell
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test --all-targets --quiet
git diff --check
```

Editor diagnostics for the changed Rust and Markdown files must also be
checked in VS Code. A diagnostic result is recorded with the validation run;
it is not inferred from a successful Cargo command.

## Manual Terminal Smoke Procedure

These checks require an already configured interactive Copilot SDK session or
a working local provider. Do not automate credentials, paste API keys into
the procedure, fabricate SDK events, or change terminal settings as part of
the check. If authentication or the provider is unavailable, record the row
as `blocked`, not `passed`.

### Capture Environment

From the repository root, capture this in each terminal environment:

```powershell
Get-Date -Format o
$PSVersionTable.PSVersion.ToString()
$Host.Name
$env:WT_SESSION
$env:TERM
rustc --version
cargo --version
git rev-parse --short HEAD
```

Use the same project command in each environment:

```powershell
$project = (Get-Location).Path
cargo run -- --project $project
```

Windows Terminal and the VS Code integrated terminal are run with their
normal PowerShell profiles. For legacy conhost, open `conhost.exe`, start
PowerShell, change to the repository root, and run the same command. Do not
compare observations from different commits or different project folders.

### Interaction Matrix

| Action | Observe | Pass condition |
| --- | --- | --- |
| Send a normal prompt and let assistant output stream | Live assistant rows while tokens arrive | No viewport jump; complete rows remain in scrollback and only the partial tail changes. |
| Request a long-running shell command that emits output in several steps | Bash header and live progress | Progress remains in the live region, shows recent output, and disappears when the final result arrives. |
| Send several messages, then use normal terminal scrollback selection | Main-screen history | Rows remain selectable and are not replaced by a fullscreen overlay. |
| Resize from wide to narrow and back while output is live | Input, live rows, and committed history | Live content rewraps; history is not duplicated, erased, or recommitted. |

| Type `cafe`, CJK, combining characters, `👩‍💻`, and a tab in the prompt | Prompt width and cursor movement | Grapheme clusters stay intact; tabs expand; `❯` and continuation rows keep their intended columns. |
| Ask the agent to run commands that emit named, indexed, and truecolor SGR plus underline | Tool output colors | Supported colors remain visible, underline is removed, and control bytes do not escape into the terminal. |
