picopilot — setup wizard flow prototype

Question this answers: does the setup-wizard's screen sequence — entry → add a provider (or connect Copilot) → repeat or finish — hold together across the awkward cases? In particular: what happens when a user configures both Copilot and an OpenAI-compatible provider in the same pass, and which one should become default_provider? This prototype proposes "whichever was configured most recently in the wizard wins" — consistent with how default_provider already behaves everywhere else in the design (it always tracks "last used"), rather than inventing a special wizard-only tie-break rule. Free-play on the left/right panels, or step through the scenarios below. Nothing here is wired into picopilot's real TUI — it's throwaway code to react to, per .wayfinder/provider-config/tickets/06-setup-wizard-flow-prototype.md.
